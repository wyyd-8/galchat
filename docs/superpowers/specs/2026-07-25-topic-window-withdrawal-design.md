# 话题窗口与撤回设计

## 目标

在不改变单聊与群聊各自上下文策略的前提下，让两者都能安全撤回最多三轮，并让向量库、热上下文与存读档回到同一时间点。

## 统一窗口规则

新增一个无状态的 `TopicWindowPolicy(contextTopicCount, maxWithdrawRounds)`，只负责计算：

- 新边界加入后，哪个 `[start, end)` 话题刚滑出热上下文、需要写入向量库；
- 最新边界移除后，哪个 `[start, end)` 话题重新进入热上下文、需要从向量库删除；
- 当前上下文的起点；
- 回滚计算最多需要保留多少个边界。

单聊配置为 `3 + 3 = 6` 个边界，普通群聊配置为 `2 + 3 = 5` 个边界。该类不读写 Redis、数据库或向量库；单聊和群聊仍保留独立的持久化及撤回服务。

## 单聊

### 边界

Redis 中的 `TopicBoundary` 改为：

- `startIds`：按旧到新排列的完整边界队列，最多六个；
- `lastCheckedMessageId`：最后参与话题判断的消息。

模型上下文从 `startIds` 倒数第三个边界开始。加入新边界时，刚滑出倒数三个边界的区间立即向量化，然后只裁掉超过六个的最旧边界。

### 逻辑轮与撤回

单聊逻辑轮包括：

- 用户消息及其关联的助手回复、思考、工具调用、自动检索信息和好感日志；
- `userMessageId == null` 的主动助手消息；
- 已撤回占位行。

撤回严格按逻辑轮倒序执行。主动消息可单独撤回；如果它是最新轮，必须先撤回它才能撤回更早的用户轮。撤回保留原锚点行并将其改为 `withdrawn`，其余关联行删除。

若撤回轮创建了最新话题边界，则从队列移除该边界，并删除撤回后重新进入三个热话题窗口的精确向量文档。若该轮未创建新边界，边界队列不变，只回退 `lastCheckedMessageId`。仍保留最多连续撤回三轮的限制。

## 普通群聊

### 边界

`group_chat_topic` 继续保存完整历史，不物理裁剪。普通群聊运行时仅查询最近五个边界用于回滚计算，模型上下文仍从倒数第二个边界开始。

加入新边界时，将刚滑出两个热话题窗口的区间向量化。关闭群聊前，将最后两个未向量化话题写入向量库。

### 整轮撤回

新增普通群聊整轮撤回接口。撤回仅允许：

- 会话处于 `active`；
- `mode == chat`；
- 当前没有生成任务持有会话锁；
- 连续撤回数小于三。

撤回一轮时：

1. 删除该 `group_chat_turn` 下的全部消息；
2. 删除回复步骤和工具调用；
3. 回滚并删除绑定为 `GROUP_REPLY_STEP` 的好感日志；
4. 将本轮关联的回复计划项重置为 `pending`；
5. 如果触发消息创建了边界，删除该边界，并删除重新进入两个热话题窗口的精确向量；
6. 保留 `group_chat_turn` 行并把状态改为 `withdrawn`，作为连续撤回计数占位。

TRPG 模式不开放该接口。

## 向量一致性

单聊与群聊向量文档继续使用确定性 ID。新增按精确 `[start, end)` 删除文档的能力，撤回不使用相似度删除，也不做大范围模糊清理。

已关闭群聊不参与热原文补齐；关闭动作先向量化末尾两个话题，再设置 `closed`。

## 存读档

存档格式升级，不兼容旧快照。

单聊快照改动：

- `TopicBoundarySnapshot` 保存完整 `startIds`，不再保存 `previousStartId/currentStartId`；
- 每个角色保存最近三个“逻辑轮”，包括用户轮、主动助手轮和撤回占位，而不再只保存用户消息轮。

普通群聊快照新增：

- 每个存档时仍活跃的普通群聊保存最近三个 `group_chat_turn`；
- 同时保存这些轮的消息、回复步骤、工具调用、`GROUP_REPLY_STEP` 好感日志；
- 保存该群聊最近五个话题边界。

读档先执行现有的 max-id 清理，再恢复上述最近轮和边界。单聊按恢复后的倒数三个边界清理不应存在的热区向量；普通群聊按恢复后的倒数两个边界清理热区向量，并重建最近五个边界中应处于冷区的至多三个区间。回复计划仍沿用现有读档后重建逻辑，不进入快照。

## 非目标

- 不为 TRPG 增加另一套撤回；
- 不保存模型思考；
- 不改变普通群聊两个话题、单聊三个话题的上下文数量；
- 不兼容旧存档或旧 Redis 边界 JSON。
