# 《骑士学院》角色包设计

## 目标与范围

在已有《骑士学院》世界归档 JSON 中加入核心角色模板，使归档文件可一次性导入世界、世界详情与角色。角色资料综合 KC1 与 KC2 剧本，但时间锚点固定在 KC2 二年级新学期开始，只使用此时已经成立的共同事实。

收录角色限定为两部标题界面“选择角色／角色”列表中的人物与默认主角，排除卡培拉，共 14 名：

- 阿尔戈
- 格兰特利
- 奥斯卡
- 提奥
- 保尔
- 尤利乌斯
- 迪德里克
- 西利欧
- 赫尔曼
- 希埃亚特
- 巴滕
- 菲力克斯
- 伽米尔
- 贝福里特

不因戏份、职务或世界地位额外收录其他教官、骑士、学生、龙或剧情配角。

## 译名规则

同一人物、国家、地点、组织或概念在两部中的中文名称不同时，以 KC1 译名为准。整个归档文件统一应用此规则，包括 `world.background`、`details` 与 `characters`。

KC1 已经给出名称的实体不使用 KC2 异名作为主称。只在 KC1 没有对应名称、而该实体确实属于 KC2 新增设定时沿用 KC2 名称。无法可靠确认对应关系的近似名称不强行合并。

## 角色字段设计

每名角色使用现有 `WorldArchiveDTO.CharacterArchive` 结构：

```json
{
  "name": "角色姓名",
  "image": null,
  "background": "身份、出身、经历、关系与能力",
  "personality": "价值观、情绪习惯、优缺点与说话方式",
  "cocPlayStyle": "调查、社交、战斗和危机中的行动倾向",
  "favorability": {
    "0": "尚未建立信任时的表现",
    "25": "逐渐熟悉并接纳对方时的表现",
    "50": "形成信赖、愿意托付或袒露心事时的表现",
    "75": "高度重视对方时的表现"
  },
  "initFavor": 0
}
```

`background` 只记录截至时间锚点已经稳定成立的资料，不把章节摘要写成履历。`personality` 同时描述优点与局限，并保留角色可在互动中改变判断的空间。`cocPlayStyle` 是通用行动逻辑，不把角色强行改写成《克苏鲁的呼唤》调查员，也不预设玩家选择。

`favorability` 使用系统能够识别的数值阈值键 `"0"`、`"25"`、`"50"`、`"75"`，分别对应陌生、熟悉、信赖与亲密阶段；每个阶段的文字依据角色个性单独撰写。阶段描述聚焦信任、交流与行为变化，不预设恋爱成立。

## 初始亲和度

`initFavor` 表示角色面对普通陌生人时的自然亲和程度，不代表角色对阿尔戈、玩家或特定路线的既有好感。数值依据以下因素综合设定：

- 外向、乐于结交和主动照顾陌生人者取较高值。
- 礼貌但保持身份距离者取中间值。
- 寡言、戒备、傲慢或不轻易信任他人者取较低值。
- 职务上的接待义务不等同于私人亲和；公开亲切但内心谨慎的角色不取极高值。

所有数值保持在系统接受的 0–100 范围内，并在角色之间形成可解释的相对差异。数值不编码恋爱进度、路线完成度或结局状态。

## 主角处理

阿尔戈按默认姓名建立角色模板。其背景可写奥库利村渔家出身、特别保送入学、骑士志向以及剧本明确的持续能力，但不替玩家决定关键分支、恋爱对象或结局。

阿尔戈的性格采用两部共同表现出的稳定底色，例如好奇、务实、愿意帮助他人和面对未知时的行动力；对可能受玩家选择影响的态度使用开放描述。

## 剧情与剧透边界

可以写入：

- 开场前的出身、身份、家庭与长期目标。
- KC1 后已成为 KC2 公共现状的非结局共同事件。
- 截至 KC2 新学期开始已经公开且持续有效的职位、同学关系和能力信息。
- 剧情揭示但本质上属于角色稳定特征的事实。

不得写入：

- KC1 或 KC2 的结局、后日谈与结局卡内容。
- 恋爱结果、攻略路线、玩家选择、好感进度或室友分支结果。
- Bad End、失败线和互相冲突的分支状态。
- 终局才揭露或才成立的牺牲、去向、身份及关系变化。
- 为增强戏剧性而补写原文没有确认的心理动机。

## 质量与校验

1. `characters` 恰好包含 14 个唯一姓名，且不包含卡培拉。
2. 每个角色拥有 `name`、`image`、`background`、`personality`、`cocPlayStyle`、`favorability` 和 `initFavor`。
3. `image` 统一为 `null`；好感阈值必须恰好为 `"0"`、`"25"`、`"50"`、`"75"`，四档内容均非空。
4. `initFavor` 依据陌生人亲和度设置，处于 0–100 范围且不编码剧情关系。
5. 全文扫描已知 KC2 异名，确认 KC1 已命名实体均使用 KC1 译名。
6. 扫描“结局”“后日谈”“恋爱成立”“路线”等高风险内容，并逐项人工复核。
7. 角色的能力、经历和关系均能回溯到 KC1 或 KC2 原文。
8. JSON 可被标准解析器读取并符合 `WorldArchiveDTO`，相关项目测试通过。
