# 《骑士学院》世界包设计

## 目标

根据《骑士学院》KC1 与 KC2 的完整中文剧本，整理一个能够被 GalChat 现有世界归档接口直接导入的 JSON 世界包。本阶段只构建世界模板与世界详情，不创建角色模板。

两部作品属于同一连续世界。跨作品出现的同名人物、地点、组织和概念视为同一实体；翻译差异不重复建条目。若同一实体在两部中的中文名称不同，统一采用 KC1 的译名。

## 输入与输出

输入来源：

- `/Users/wyyd/Downloads/项目/kc1完整中文剧本.txt`
- `/Users/wyyd/Downloads/项目/完整中文剧本_KC2.txt`

输出文件：

- `data/worlds/knight-academy-world.json`

输出遵循 `WorldArchiveDTO` 当前使用的归档格式：

```json
{
  "formatVersion": 1,
  "world": {
    "name": "骑士学院",
    "image": null,
    "author": "《骑士学院》KC1/KC2 剧本设定整理",
    "background": "世界总体背景",
    "visible": false
  },
  "details": [
    {
      "about": "条目标题",
      "details": "条目正文"
    }
  ],
  "characters": []
}
```

`visible` 默认为 `false`，使导入后的世界保持私有。`image` 暂不引用无法确认授权和稳定性的外部资源。

## 内容架构

采用混合百科式组织。

`world.background` 是无需检索也应始终成立的世界总览，概括故事时代、骑士的国际职能、龙的政治地位、E.P. 与佛罗汀骑士学院的核心作用，不堆叠人物剧情。

`world_detail` 按主题拆成约 25–40 个可独立检索的条目：

1. 世界基础规则：文明与交通、骑士制度、跨境特权、骑士头衔。
2. 超常体系：E.P.、E.P. 点、能力觉醒与成长、使用限制与保密原则。
3. 龙与国际秩序：龙的地位、七龙议会、龙与国家的不同关系。
4. 国家与地区：佛罗汀、哈施莱克、鲁德维戈、加尔达亚，以及剧本明确描述的其他政治实体。
5. 组织：佛罗汀中央骑士团、佛罗汀骑士学院、国际留学制度。
6. 重要地点：克莱格岛、学院设施、奥库利村、港都安格布尔及其他具有稳定设定意义的地点。
7. 社会与文化：教育、阶级、贵族与商人、海洋贸易、语言和跨国交流。
8. 既成事件：只收录已经发生、会持续影响世界现状、且不依赖结局路线的事件。

条目以一个清晰主题为中心。若两个事实经常会被同一个问题查询，可以合并；若一个条目同时回答多个无关问题，则拆分。

## 剧情与剧透边界

可以收录：

- 作品开场前已经发生的历史和人物共同认知。
- KC1、KC2 中已经发生并改变公共现状的非结局事件。
- 通过剧情揭示、但本质上属于稳定世界规则或历史事实的内容。
- 能解释 KC2 世界状态的 KC1 前情，但只写确定发生的共同线事实。

不得收录：

- KC1 或 KC2 的结局内容。
- 恋爱结果、角色路线归属、玩家选择和好感状态。
- Bad End、失败线或彼此冲突的分支结果。
- 只有在终局才成立的身份、牺牲、去向或关系变化。
- 将悬念答案直接写入无关条目的内容。

对可能具有轻度剧透但确实影响现状的事件，正文只记录结果及公共影响，不复述完整场景过程。

## 实体与译名统一

优先使用 KC1 的中文译名。若同一实体在 KC2 中采用不同译名，世界背景、世界详情与角色模板仍使用 KC1 名称，不以 KC2 译名替代。例如：

- 弗罗汀，不使用 KC2 的“佛罗汀”
- 哈什莱希，不使用 KC2 的“哈施莱克”
- 鲁德维戈，不使用 KC2 的“鲁多维科”
- 克莱格岛，不使用 KC2 的“克雷格岛”

同一实体只建立一个主条目。人名只在解释国家、组织、规则或既成事件时出现，不在本阶段建立角色档案。无法从上下文可靠判定为同一实体的近似名称不强行合并。

## 事实提取与证据规则

每条设定必须能由至少一处剧本原文支持。跨作品内容按以下优先级处理：

1. 两部一致的陈述。
2. KC2 对 KC1 设定的明确补充或更新。
3. 更具体、且不与其他文本冲突的陈述。
4. 叙述者推测、玩笑和角色不可靠判断不作为确定事实，除非另有文本印证。

出现冲突时，不擅自补完原作未说明的因果；正文使用“剧本未明确说明”或省略该细节。最终 JSON 不包含引文、行号和制作过程说明，只保留适合角色聊天检索的自然语言设定。

## 长度与检索质量

- `about` 使用简短且唯一的中文标题，并包含主要检索关键词。
- 每条 `details` 不超过后端限制的 2000 个 Java 字符。
- 单条正文以约 250–900 个汉字为目标；内容较多时拆分。
- 重要别名、国家名、制度名和缩写在正文中自然出现。
- 避免在多个条目整段重复同一信息，必要的交叉关系用一句话提示。
- 不把章节摘要或对白流水账当成世界设定。

## 校验

生成后执行以下检查：

1. JSON 可以被标准解析器读取，且结构符合 `WorldArchiveDTO`。
2. `formatVersion` 为 `1`，`world.name` 与 `world.background` 非空。
3. `characters` 是空数组。
4. 每个 `details` 元素的 `details` 非空且不超过 2000 个 Java 字符。
5. `about` 不重复，译名和同名实体没有被重复建档。
6. 扫描“结局”“Ending”“恋爱”“路线”等高风险表述，人工复核剧透。
7. 抽查每条世界详情均能回溯到 KC1 或 KC2 的原文依据。
8. 使用项目测试验证本次新增数据文件未影响现有代码。

## 不在本阶段处理

- 角色模板、角色头像、性格、好感度和聊天扮演提示。
- 原剧情的逐章复刻或可游玩模组。
- 世界封面制作。
- 数据库直接写入或公开发布。
