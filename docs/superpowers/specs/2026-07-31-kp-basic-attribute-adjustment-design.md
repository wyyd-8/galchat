# KP 基础属性修正工具设计

## 1. 目标

为 TRPG 群聊中的 KP 增加一个简要属性修改工具。KP 按人物卡准确名称选择调查员或 NPC，并为八项基础属性提供增量修正值。后端更新指定字段，重新计算伤害加值（DB）和体格（build），其他人物卡字段保持不变。

同时修正建卡校验：新建人物卡时，八项基础属性必须分别处于 `10–90`。

## 2. 工具接口

新增 KP 工具：

```text
adjustBasicAttributes(characterName, adjustments)
```

`characterName` 是当前跑团中人物卡的准确名称。`adjustments` 使用专用 DTO，包含以下八个可选整数：

- `str`
- `con`
- `siz`
- `dex`
- `app`
- `int`
- `pow`
- `edu`

未提供的字段不修改。至少需要提供一个字段。

示例：

```json
{
  "characterName": "林恩",
  "adjustments": {
    "str": 10,
    "app": -5
  }
}
```

工具放在现有 `KpModuleTools` 中，沿用以下规则：

- 仅 KP 可以调用。
- 只在当前跑团内按准确人物卡名称匹配调查员或 NPC。
- 零条或多条匹配均报错。
- `returnDirect = false`，工具完成后 KP 继续回复。
- 通过 `KpModuleTools` 现有阶段挂载规则提供给 KP。

## 3. 修正规则

每个指定字段按以下公式更新：

```text
newValue = clamp(currentValue + correction, 0, 100)
```

其中 `clamp` 将结果限制在闭区间 `0–100`。

示例：

- 当前值 `10`，修正值 `-15`，结果为 `0`。
- 当前值 `95`，修正值 `10`，结果为 `100`。
- 当前值 `40`，修正值 `0`，结果仍为 `40`。

修正值必须是整数。请求为空或八个字段全部缺失时返回业务错误，不写数据库。

## 4. 派生字段

基础字段更新后，使用现有 `CharacterCardRules` 和修改后的 `STR + SIZ` 重新计算：

- `damage_bonus`
- `build`

虽然现有规则计算器还能计算 MOV、HP、SAN 和 MP，本工具不会写入这些结果。以下字段全部保持原值：

- MOV
- HP 当前值与上限
- SAN 当前值与上限
- MP 当前值与上限
- 幸运
- 护甲
- 技能、武器和人物背景
- 重伤、昏迷、濒死、死亡和疯狂等状态
- KP 快速笔记

即使 CON、DEX 或 POW 被修改，也不重新计算上述字段。

## 5. 数据一致性

属性修正、DB/build 重算和人物卡更新时间更新在同一个事务中完成，并只执行一次人物卡持久化。校验或匹配失败时不产生部分更新。

工具返回本次实际变更结果，包括人物卡名称、每个指定字段的修改前后值，以及重算后的 DB/build，供 KP 组织后续公开回复。

## 6. 建卡校验

新建人物卡时，`STR/CON/SIZ/DEX/APP/INT/POW/EDU` 每项必须处于闭区间 `10–90`。小于 `10` 或大于 `90` 时拒绝建卡。

现有“八项基础属性总和不超过 460”规则保持不变。运行时 KP 修正不受总和上限约束，只应用 `0–100` 钳制规则。

## 7. 测试

测试覆盖：

- 只修改请求中指定的基础字段。
- 正数、负数和零修正。
- 低于 `0` 时钳制为 `0`，高于 `100` 时钳制为 `100`。
- STR/SIZ 修改后 DB/build 按现有档位重算。
- CON、DEX、POW 等修改后 MOV、HP、SAN、MP 等保持不变。
- 空修正请求不写数据库。
- 准确名称匹配、不存在、重名和非 KP 调用。
- 工具 Schema 暴露八个可选整数修正字段，不接收人物卡 ID。
- 建卡属性 `10` 和 `90` 可接受，`9` 和 `91` 被拒绝。
- 建卡总和上限规则保持有效。
