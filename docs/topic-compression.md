# 单聊与普通群聊的话题压缩

## 窗口与切换

- 单聊保留最近 3 个话题，普通群聊保留最近 2 个话题，窗口内使用原始消息。
- 评分只读取最新话题及本次用户消息，不混入更早话题或后台任务启动后生成的回复。
- 模型输出 0–100 的整数评分；评分使用 `deepseek-flash` 并开启思考。
- 硬上限为单聊 4000、普通群聊 8000，按消息正文的 Java UTF-16 长度计算，不是 token 数。

设当前话题加本次用户消息的长度为 L，硬上限为 H，模型评分为 S：

```text
P = clamp((L - 0.2H) / (0.6H), 0, 1)
W = 0.75 × S / 100 + 0.25 × P
```

达到硬上限、S > 90 或 W ≥ 0.75 时切换。90 分本身不会绕过加权条件。
没有历史消息时只建立初始话题。评分异常时保留当前话题；达到容量上限时跳过评分模型。
长度、评分、压力、加权值及判定原因只记录日志。

## 逐条摘要

切换使最旧话题退出上下文窗口时，才对该话题归档。模型一次读取完整话题，
为每条消息分别返回 `messageId` 和 `compressedContent`，不合并消息。
摘要使用项目配置的原模型，关闭思考；提示词与评分提示词均重新编写。

摘要要求保留有意义的括号动作、否定、条件、疑问与不确定性，不主动解析或替换人称、
模糊指代及相对时间。程序校验消息条数、ID、顺序及非空正文，并从原记录附加发言者、时间戳。
单条摘要比原消息长时回退到原文；结构无效则放弃本次归档，不推进边界。
结构校验不能保证模型没有语义偏移，仍需结合实际样本检查摘要质量。

## 异步执行与锁

仅单聊和普通群聊使用此异步流程，TRPG 的运行流程不变。
用户消息保存后，后台执行评分、摘要和归档；当前回复使用原窗口立即开始调用模型。
后台准备完成也不会在同一轮的多个群聊发言之间切换窗口。
回复与后台任务都结束后才发布新边界并释放会话锁。

取消输出会先清理回复分支，再等待后台任务结束后释放锁。
任务拒绝、摘要异常或归档失败时保留原窗口，后续轮次可重试。
评分调用上限为 30 秒，摘要和归档 embedding 调用上限为 120 秒；
底层 HTTP 客户端可能有更短的超时。在线检索的 embedding 调用沿用原方式。
后台任务使用独立线程池，饱和时跳过任务，不回退到请求线程阻塞回复启动。

本次不修改已有归档数据，不进行历史摘要回填。

## 回归覆盖

- `TopicCompressionPolicyTest`：评分阈值、容量边界和逐条摘要结构。
- `CommonConfigurationTest`：评分模型与思考选项、摘要继承原模型且关闭思考。
- `TopicBoundaryForwardTest`：只评分最新话题，排除本轮后续消息。
- `TopicCompressionTaskTest`、`SingleChatCompressionFlowTest`、`GroupChatServiceTest`：
  先输出回复、延后发布边界与解锁，以及取消、失败和任务拒绝。
- `ChatHistoryCompressionTest`、`GroupTopicVectorServiceTest`：发言者归属及无效摘要拦截。
- `TopicModelCallTest`：模型超时后不继续归档写入，检索沿用原调用方式。
