# TRPG Agent 场景、裁定与记忆设计

## 1. 文档目的

本文档定义 GalChat 跑团功能第一阶段的产品语义、职责边界、上下文范围和运行流程，用于指导后续实现与验证。

第一阶段面向规则和流程相对有限的小型模组。设计优先保证调查员自主性、KP 最终裁定权、决策过程可追溯，以及跨场景推理的连续性，不在基础循环尚未验证前引入复杂的多 Agent 工作流、目标树或多级摘要。

规则知识以 [规则书 Markdown 索引](../output/pdf/README.md) 为来源。KP 可以查询规则知识并调用检定能力，但规则书原文和工具原始输出不直接作为长期场景记忆。

## 2. 第一阶段范围

### 2.1 参与者

第一阶段包含以下参与者：

- 用户调查员：由用户控制。用户决定该调查员的行动，并可以向其他调查员提出建议，但不能替其他调查员作决定。
- 玩家 Agent 调查员：由玩家 Agent 独立控制。它与用户调查员共同探索，并对自己的判断、行动和是否继续当前场景探索负责。
- KP Agent：控制环境与 NPC，提供可观察信息，决定是否需要检定、使用什么检定和如何解释结果，并维护场景事实的一致性。
- 掷骰与计算工具：负责生成骰点、计算成功等级和处理明确的规则计算，不负责决定剧情走向。

所有调查员组成一个共同调查团队，围绕同一个场景目标发掘真相。调查员可以采取不同方法和行动，但不为每个调查员维护独立的长期探索目标。

### 2.2 场景类型

第一阶段包含：

- 探索场景：所有非战斗过程，包括调查、交涉、研究、搜索、移动和一般叙事互动。
- 战斗过程：拥有独立回合和规则处理，结束后向所属场景返回必要结果。

第一阶段暂不实现追逐过程。理智规则只实现临时性疯狂，不实现不定性疯狂和永久性疯狂。小型模组默认不进行逐发弹药等不影响主要剧情的精细资源管理。

## 3. 核心设计原则

### 3.1 KP 拥有最终裁定权

调查员决定角色想尝试什么，KP 决定该尝试是否能够直接完成、是否需要检定，以及检定使用的技能、属性、难度和其他条件。

需要检定时，由 KP 发起检定并调用掷骰与计算工具。骰点和计算结果由工具产生，KP 不能修改工具结果；KP 根据行动目标、骰点结果和当前场景给出简短说明。

KP 的裁定权不等于替调查员决定下一步行动：

- 检定成功后，KP 简短说明目标是否达成及调查员能够观察到的直接结果，调查员自行决定下一步做什么。
- 普通检定失败后，KP 简短说明本次目标未达成或当前能够确认的直接结果，调查员自行决定接受失败、改变行动或尝试孤注一掷。
- 孤注一掷失败后，KP 可以决定严重后果和相应的场景变化。

调查员可以描述自己的言语、动作以及在已确认结果范围内如何继续行动，但不能宣布未知事实、控制 NPC、修改环境或自行确定检定结果。

### 3.2 场景是上下文与记忆的基本边界

所有聊天、决策说明、调查员行动、KP 反馈、检定结果和重要事件都属于一个明确场景。

当前场景保留完整语义上下文。场景正式结束后生成一个场景概要；进入新场景时，加载所有历史场景概要和新场景的完整上下文，不加载历史场景的全部原始过程，也不对历史场景概要再次概括。

“完整语义上下文”不包括模型的原始思维链，也不包括对后续判断没有意义的大段规则原文或工具原始输出。

### 3.3 运行状态与自然语言记忆分离

角色生命值、理智值、临时性疯狂、伤害、重要物品和线索是否获得等确定运行状态，不能只存在于聊天或概要中。

结构化状态只用于保存运行和规则计算所必需的数据，不重复保存概要中的完整叙事。场景记录描述发生过程，场景概要支撑跨场景推理，结构化状态负责提供当前有效数值；三者发生冲突时，以经过裁定并已提交的运行状态为准。

### 3.4 已知信息与秘密信息分离

共享场景目标、玩家 Agent 决策和调查员行动只能使用调查员已经知道或当前能够观察到的信息。

KP 可以读取模组真相、未公开线索、NPC 隐藏状态和规则知识，但不得把这些内容提前写入调查员可见上下文、决策说明或共享场景目标。

## 4. 共享场景目标

每个场景拥有一个对所有调查员公开的共享场景目标，用来说明团队根据当前已知信息希望在本场景解决什么问题。

共享场景目标必须：

- 只基于调查员已经知道或能够观察到的信息。
- 描述需要解决的问题，不提前泄露答案、幕后真相或未获得线索。
- 足够明确，能够帮助玩家 Agent 判断信息价值并避免探索方向持续偏移。
- 在场景期间保持相对稳定。
- 在获得足以改变调查方向的重要新信息后允许调整。

示例：调查废弃病院，确认失踪记者是否到过这里，并寻找能够继续追踪他的线索。

共享场景目标不是 KP 的幕后计划，也不是固定剧情结局。KP 掌握的场景真相和可能发展属于私密模组状态，不能写入共享场景目标。

玩家 Agent 不维护独立的长期探索目标。每个玩家 Agent 只在本轮决策中说明自己准备采取的下一步行动，不同调查员可以围绕同一目标选择不同方向。

## 5. 调查员参与状态与场景结束

### 5.1 单个调查员结束探索

每个调查员都可以独立确认结束自己在当前场景中的探索。

玩家 Agent 在决策阶段确认结束后：

- 不再为该调查员安排当前场景中的后续主动探索轮次。
- 不再要求该调查员继续提出行动。
- 该调查员已经完成的决策保留在其自身私有场景上下文中；公开行动和获得的信息仍保留在公开场景上下文中。
- KP 仍可记录环境或其他角色对该调查员造成的被动影响。
- 该调查员在进入新场景前不再恢复当前场景的主动探索。

用户只能决定自己的调查员是否结束探索，可以建议其他调查员结束，但不能直接修改其他调查员的参与状态。

### 5.2 场景正式结束

只有当前场景中的所有调查员都已经确认结束探索，场景才可以正式结束。

即使所有调查员都已确认结束，仍应先完成已经开始的行动、检定、孤注一掷或战斗过程。不存在待处理过程后，KP 才确认最终状态并生成场景概要。

单个调查员结束探索不会结束整个场景，也不会阻止其他调查员继续行动。

## 6. 玩家 Agent 的决策与行动

玩家 Agent 的每次主动探索包含“决策”和“行动”两个连续语义部分。二者由同一个 ReplyStep、同一次业务层模型调用依次生成：模型先输出可展示决策，再输出公开行动。行动文本在自回归生成中直接以前面的决策文本为依据，不重复读取或重建第二份上下文。

### 6.1 决策行为：观察与思考

观察与思考属于同一个决策行为。玩家 Agent 根据 KP 最新提供的信息，结合历史场景概要、当前场景过程、共享场景目标和角色状态，判断信息之间的联系，并决定下一步尝试什么。

生成决策时可以使用：

- 角色身份、性格和当前状态。
- 当前共享场景目标。
- 所有已结束场景的概要。
- 当前场景中该调查员有权知道的完整语义上下文。
- KP 最新提供的观察、检定结果或行动结果。
- 当前剩余场景轮数和必要限制。
- 当前调用允许使用的角色行动工具及其结果。

每次决策必须生成一个完整、连贯的自然语言段落，并向用户展示。这个段落应当自然地串联当前值得关注的观察、相关线索之间的联系、调查员据此形成的判断、共享目标的当前进展，以及下一步准备采取的行动；如果调查员决定结束自己的场景探索，段落中应说明理由。

向用户展示和持久化的决策记录不使用 JSON、字段表、固定标签或分项模板。服务端可以使用不会保存和展示的传输标签拆分决策与行动。决策应当包含足以理解判断依据的外显逻辑链条，但不是模型的原始思维链，不应包含冗长的候选方案穷举、内部提示词、与最终判断无关的推演或秘密信息。

决策段落只对用户和作出决策的角色自身可见。它不进入公开消息、KP 上下文、其他角色上下文或场景概要。同一角色后续轮次可以读取自己在当前场景中已经完成的决策。

### 6.2 行动行为

行动部分负责把前文已经确定的意图转化为符合角色身份的实际表达，包括角色说的话、动作和尝试。

行动与决策共享同一次调用的上下文，但只能落实前文决策，不重新选择目标。行动生成可使用：

- 角色身份、性格和表达要求。
- 当前场景中与行动直接相关的上下文。
- 当前共享场景目标。
- 同一输出中位于行动之前的完整决策段落。

场景探索中的结束探索工具属于行动语义。需要调用时，工具调用及结果回传必须先完成，模型再统一输出决策与行动；行动正文仍不得重新分析线索或改变已经形成的行动意图。

行动只能描述调查员说什么、做什么或尝试什么，不能宣布未知事实、决定 NPC 反应、修改场景状态或自行声明检定成功。

如果角色决定结束自己的场景探索，仍需通过行动工具更新参与状态，并输出简短公开行动说明。

## 7. KP Agent 的职责

KP Agent 负责：

- 在场景开始时提供初始可观察信息，并根据当前已知信息建立共享场景目标。
- 控制环境和 NPC，维护模组真相与调查员已知信息之间的边界。
- 根据用户及玩家 Agent 的行动提供新的可观察信息。
- 判断行动能否直接完成，避免为没有冲突或风险的日常行为进行无意义检定。
- 判断是否需要检定，并确定检定目标、技能或属性、难度及其他规则条件。
- 在需要时查询规则知识并调用掷骰与计算工具。
- 对普通成功或失败给出简短、直接的结果说明，把下一步行动权交还给调查员。
- 在孤注一掷失败后决定严重后果和场景变化。
- 在临时性疯狂发生时确定或生成疯狂症状和行为约束，但不替调查员决定约束范围内的完整行动。
- 维护场景事实和运行状态的一致性。
- 在所有调查员结束探索且待处理过程完成后，确认最终状态并提供场景概要所需信息。

KP 不替用户或玩家 Agent 选择普通的下一步行动，也不把秘密信息提前写入调查员可见上下文。

## 8. 检定与孤注一掷

### 8.1 发起检定

调查员只描述行动和目标，不主动调用检定能力。KP 判断行动是否需要检定。

如需检定，KP 至少需要确定：

- 执行检定的调查员。
- 调查员希望实现的目标。
- 使用的技能或属性。
- 检定难度。
- 奖励骰、惩罚骰或其他适用条件。
- 检定是否公开。
- 失败后是否允许孤注一掷。

掷骰与计算工具生成骰点和成功等级。KP 根据工具结果给出简短说明，说明目标是否达成以及调查员能够直接观察到什么。

### 8.2 成功后的流程

普通检定成功后：

1. KP 简短确认目标已经达成，并说明必要的直接结果。
2. 调查员在下一次决策中观察该结果，判断它对共享场景目标的意义。
3. 调查员自行决定下一步行动。

调查员可以在后续行动中描述自己如何利用已经确认的成功结果，但不能借此增加未被裁定的新事实或替 NPC 作出反应。

### 8.3 普通失败后的流程

普通检定失败后：

1. KP 简短说明本次目标没有达成，或说明调查员当前能够确认的直接结果。
2. 本次失败成为下一次决策的新观察。
3. 调查员自行决定接受失败、改变方法、采取其他行动，或在规则允许时进行孤注一掷。

普通失败不授权 KP 自动替调查员选择下一步行动，也不自动引入只有孤注一掷失败才应出现的严重后果。

### 8.4 孤注一掷

孤注一掷不是自动重掷，而是普通失败后新的一次完整“观察与思考—行动—裁定”过程。

首次失败后，系统保留待处理检定，至少记录：

- 调查员和原始行动目标。
- 使用的技能或属性与难度。
- 首次骰点和结果。
- 是否允许孤注一掷。
- 当前处理状态。

如果玩家 Agent 决定孤注一掷：

1. 它在新的决策段落中说明如何理解首次失败，以及准备付出什么额外努力、时间或风险来继续实现同一目标。
2. 它在行动阶段实际表达新的做法。
3. KP 判断该行动是否仍针对原目标、是否足以构成孤注一掷，以及规则是否允许。
4. KP 可以在掷骰前说明或暗示孤注一掷失败的风险。
5. 掷骰与计算工具执行孤注一掷。
6. 成功时，KP 简短说明目标达成，调查员在下一轮决定后续行动。
7. 失败时，KP 决定严重后果和场景变化，并将其作为下一轮的新观察。
8. 无论成功或失败，孤注一掷完成后都关闭对应的待处理检定。

孤注一掷必须延续原始目标，不能通过新的描述偷偷替换成无关目标。战斗检定、理智检定、伤害和其他规则禁止的检定不能孤注一掷。

## 9. 临时性疯狂

第一阶段只实现临时性疯狂。

当规则条件触发临时性疯狂时：

1. KP 发起必要检定，掷骰与计算工具处理骰点、理智损失、症状和持续时间等明确计算。
2. KP 根据结果给出简短说明，并确定当前疯狂症状对调查员施加的行为约束。
3. 玩家 Agent 保留角色控制权，在后续决策和行动中自行决定如何在约束范围内表现和行动。
4. 如果玩家 Agent 的行动明显违反仍然有效的疯狂约束，KP 应拒绝该行动或要求其在约束内重新表达。
5. 临时性疯狂结束后更新角色状态，恢复正常决策范围。

KP 决定疯狂带来的失控边界，但不代替调查员决定边界内的完整行动。

## 10. 探索场景流程

对一个仍在参与当前场景的玩家 Agent 调查员，普通探索循环如下：

1. KP 给出当前可观察信息，或上一行动、检定和场景变化的简短结果。
2. 玩家 Agent 在一个 ReplyStep 和一次业务层模型调用中依次生成私有决策与公开行动。
3. 如果玩家 Agent 确认结束自己的场景探索，在同一次调用的工具循环中更新参与状态，并输出公开说明。
4. 服务端分别保存私有决策和公开行动；原始模型 reasoning 只实时展示，不保存。
5. KP 接收行动，判断是否可以直接完成或需要检定。
6. 无需检定时，KP 给出直接结果。
7. 需要检定时，KP 发起检定，工具生成结果，KP 给出简短说明。
8. 本轮决策段落进入该角色自身的私有场景上下文；行动、骰点、KP 说明和必要状态变化进入公开场景上下文。
9. 调查员在下一次轮到自己时，根据新结果决定下一步行动。

用户调查员的行动同样由 KP 裁定，但不经过玩家 Agent 的决策和行动模型。用户自行决定后续行动，也只能确认结束自己的场景探索。

场景轮次是控制探索循环和最大轮数的产品概念，不等同于战斗轮。

## 11. 场景记忆

### 11.1 当前场景记忆

当前场景保留：

- 共享场景目标及其调整记录。
- 每个调查员当前是否继续探索。
- 用户与调查员的公开聊天内容。
- 玩家 Agent 展示给用户的完整决策段落。
- 用户和玩家 Agent 的行动。
- KP 给出的可观察信息与简短结果说明。
- 检定目标、骰点和结果。
- 待处理检定与孤注一掷的必要过程。
- 临时性疯狂的结果和有效约束。
- 战斗过程返回的最终结果。
- 对后续场景有意义的事件和状态变化。

当前场景记忆保留完整语义过程，不保存模型原始思维链，也不长期保存无意义的工具输出。

### 11.2 历史场景概要

场景正式结束后生成一个完整但简洁的概要，至少说明：

- 场景共享目标。
- 各调查员结束探索的情况。
- 场景最终结果。
- 获得的重要信息或物品。
- 发生的重要事件。
- 关键状态变化。
- 尚未解决的问题。
- 下一场景可能承接的位置或方向。

新场景加载所有历史场景概要。历史场景概要不再合并、分层或二次概括，避免进一步丢失推理所需信息。

概要只记录已经确认的事实。玩家 Agent 在决策段落中提出的判断、怀疑和线索联系，在未被后续裁定确认前不能被概要写成事实。

## 12. 探索与战斗的边界

探索场景包含所有非战斗过程，不再单独划分“叙事探索”和“标准探索”。

战斗拥有独立的内部回合和规则处理。进入战斗前，应先处理已经触发且适用于参与者的理智检定；不依赖战斗过程结束后再补做目击判定。

战斗结束后只向所属探索场景返回对后续叙事和规则有意义的结果，例如：

- 战斗胜负和结束原因。
- 调查员当前生命值、理智值及重伤、昏迷、死亡等持续状态。
- 获得或失去的重要物品和线索。
- 对后续探索有意义的环境变化或事件。

小型模组默认不要求把逐次攻击、每轮计算或逐发弹药消耗写入普通探索场景上下文。战斗内部可以保留完成规则处理所需的数据，但长期场景记忆只接收必要结果。

## 13. 最大轮数与人工确认

场景设置最大探索轮数，用于发现玩家 Agent 是否陷入重复行动、线索误判或无法推进的死胡同。

达到最大轮数时：

- 不自动结束场景。
- 暂停继续生成新的玩家 Agent 探索行动。
- 向用户展示共享场景目标、当前进展、尚未解决问题和近期重复情况。
- 由用户在产品元层决定继续当前场景、暂停场景，或要求玩家 Agent 重新评估方向。

用户在这里管理的是 AI 运行状态，而不是替其他调查员决定角色行为。用户可以要求玩家 Agent 重新观察和判断，但不能指定它必须采取某个具体角色行动。

如果用户选择暂停，已经开始的行动、检定、孤注一掷或战斗应先完成。暂停不等于所有调查员确认结束，也不自动生成正式场景概要；只有所有调查员确认结束后，场景才正式结束。

## 14. 上下文与工具边界

| 阶段 | 历史场景概要 | 当前场景信息 | 工具权限 |
| --- | --- | --- | --- |
| 玩家 Agent 决策—行动输出 | 使用全部概要 | 使用该调查员有权知道的完整上下文；同一输出中决策先于行动 | 只开放当前行动允许的工具；工具完成后统一输出决策与行动 |
| KP Agent 裁定 | 按需要使用 | 使用完整公开上下文、KP 私密模组状态和运行状态 | 允许规则查询、检定、掷骰、计算及 KP 状态工具 |
| 战斗过程 | 按需要使用 | 使用战斗所需角色和场景状态 | 允许战斗规则所需工具 |

玩家 Agent 的决策部分负责理解历史、串联线索和形成可展示判断；紧随其后的行动部分只负责落实已经形成的决定；KP 负责把行动转化为经过规则裁定的简短结果；掷骰与计算工具负责确定性计算。

## 15. 必须保持的不变量

后续设计与开发必须保持以下约束：

1. 每个场景只有一个团队共享的场景目标。
2. 共享场景目标只基于调查员已知信息，不包含 KP 幕后真相。
3. 玩家 Agent 不维护独立的长期探索目标，只形成自己的本轮行动意图。
4. 用户和玩家 Agent 分别控制自己的调查员，不能替其他调查员作决定。
5. 单个调查员可以结束自身探索，但只有所有调查员确认后场景才正式结束。
6. 观察与思考属于决策部分；决策与行动在同一个 ReplyStep、同一次业务层模型调用中依次输出。
7. 决策记录必须是向用户展示的完整自然语言段落，不使用固定字段格式。
8. 决策记录包含经过整理的外显逻辑链条，但不保存或要求模型输出原始思维链。
9. 行动只使用当前阶段允许的工具，不重新规划，也不决定未知事实和检定结果。
10. 所有检定由 KP 发起，骰点与明确计算由工具完成，剧情裁定由 KP 完成。
11. 普通成功和失败后，KP只给出简短结果，调查员自行决定下一步行动。
12. 只有孤注一掷失败授权 KP 引入相应的严重后果和场景变化。
13. 孤注一掷是首次失败后的新一轮决策与行动，且必须延续原目标。
14. 临时性疯狂由 KP 施加有效行为约束，调查员仍决定约束内的具体行动。
15. 当前场景保留完整语义上下文，历史场景保留各自概要，不对概要再次概括。
16. 结构化状态只保存运行所需事实，不重复保存完整叙事概要。
17. 战斗只向探索场景返回对后续有意义的最终结果。
18. 最大轮数只触发警告和人工确认，不自动结束场景。
19. 场景概要不能把调查员的推测写成已经确认的事实。

## 16. 第一阶段暂不设计的内容

第一阶段不主动引入：

- 多级、章节级或概要之上的二次摘要。
- 复杂的目标树、任务规划器和调查员个人长期目标。
- 独立 NPC Agent。
- 多玩家 Agent 并行协商工作流。
- 追逐过程。
- 不定性疯狂和永久性疯狂。
- 默认的逐发弹药与非关键资源管理。
- 自动反思或自我批评循环。
- 复杂的长期记忆评分和淘汰机制。
- 对所有规则查询和工具原始输出进行长期保留。

这些能力只有在基础场景循环经过实际模组验证并出现明确需求后再设计。
