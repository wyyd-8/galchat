# GalChat 1.1 宣传片：录制与动效执行稿

日期：2026-09-10。功能依据：423ddaa；完成报告、同行档案和既有聊天已在本地界面查看。本稿是制作计划，尚未录制或渲染视频。

**影片设定**

16:9 横版，先以 1920×1080、30 fps、约 160 秒制作。音乐使用 Scott Buckley《Signal to Noise》Full Mix；全片无旁白、无角色配音。先按纯音乐设计，骰子等短音效作为可选版本。

核心表达：一起经历的故事，会成为下一次同行的理由。

故事线：开始跑团 → 绑定人物卡 → 选景 → 探索 → 子场景 → 作战 → 中途单聊 → 最终场景与回顾 → 结束后单聊 → 下一次跑团。

下列时间是成片预算，不是歌曲原曲时间码。尚未导入并试听实际音频，不能据此声称某秒是音乐高潮。正式剪辑先标乐句与强弱变化，再在 140–180 秒之间调整；若截取破坏乐句，则重新选段或调整片长。

**叙事连续性**

主素材优先采用已有《古树林中》。已查看的完成记录含 4 位调查员、138 个行动轮、104 次公开检定、3 场战斗回顾；这些数字仅用于该份实际报告，不套用到补录的新会话。

人物对应保持一致：玩家／沃尔顿·红莲；格兰特利／查理·“红鬃”·汤普森；奥斯卡／埃莉诺·哈珀；阿尔戈／威尔·汤森。片中用一位同伴作主要观察对象，其余角色通过队伍与行动穿插出现，避免观众同时记忆八个名字。建议主跟格兰特利，结束后的交流可切奥斯卡。

选一件真实事件贯穿“行动—结果—单聊—回顾”，候选为木屋脱困。现有格兰特利聊天提及踹窗逃出、同伴挡住危险；奥斯卡结束后聊天回味了突围与爆炸。开拍前核对原始事件和聊天时间，确认前后对应。真实回复可以裁取完整句子；旁边重排的文本标注“对话摘录”，不把自拟宣传语伪装成角色回复。

中途交流谈刚才的选择、担心和接下来的配合；结束后交流谈印象、评价和下次同行。两次交流均选实际参团同伴。现有聊天若不发生在结局之前，就作为结束后素材，中途对话另行补录。

**素材获取路径**

| 内容 | 现在可用的来源 | 开拍安排 |
|---|---|---|
| 现有玩家与同伴人物卡 | 跑团工具 → 人物卡 | 录身份、属性、背景三个状态；无需重新生成 |
| 已发生的调查与战斗文字 | 已归档《古树林中》历史记录 | 先定位再录，保留动作与结果的对应关系 |
| 骰子动画 | 公开掷骰记录 → 播放器 → 重放动画 | 代码存在重放入口；先实机验证一条，保留原结果 |
| 最终叙述与人物后传 | 当前已结束会话末尾 | 页面稳定后录制，长文以局部镜头展示 |
| 五页完成报告 | 翻阅完成记录 | 每页录静止状态和实际翻页操作 |
| 结束后单聊 | 奥斯卡等已有单聊 | 先定位目标问答；录进入单聊及短摘录 |
| 同行档案 | 新建 CoC 跑团 → 选择参与者 | 可录已完成次数与历史条目；片尾录勾选动作 |
| 绑定过程 | 专用拍摄会话的建卡阶段 | 使用准备好的同名、同设定卡；录检查与绑定 |
| 当时的选景、子场景嵌套、战斗队列 | 归档后的当前右侧栏不能提供当时状态 | 需要专用会话补录真实过程；如果有完整隔离副本，再在副本回到相应状态 |
| 中途单聊与回到跑团 | 需核验现有聊天时间和素材 | 缺失则在专用会话中，于相关事件后实际交流 |
| PDF 导出 | 跑团工具 → 人物卡右上角 | 可选镜头，导出服务可用时录实际输出；不阻塞主片 |

补录应在单独的拍摄环境或会话完成。现有跑团读档会清理存档点之后的数据，世界存档也不是跑团全量副本，因此不把现有归档会话直接回滚作为取材手段。隔离副本必须覆盖实际运行依赖，不能假定复制世界模板就复制了会话。没有副本时，新会话只补真实功能操作；不把它的数值、骰点或台词拼接为旧会话的因果结果。

**成片分镜与录制清单**

原片统一命名为 S01_world_A.mov、S01_world_B.mov 等；关键定帧为同名 .png。A 为真实操作，B 为稳定画面。下面每一行通常拆成 2–4 个短镜头，预计约 30 个可用镜头。

| 编号／成片预算 | 具体录什么 | 需要留下的可读内容 | 后期安排 |
|---|---|---|---|
| S01／00:00–00:10 | 世界入口、模组选定、同伴勾选 | GalChat、模组名、主要同伴姓名 | 先用 2 秒建立界面；镜头缓缓靠近主同伴。首次选择不强调已有完成次数 |
| S02／00:10–00:24 | 卡片分配列表、同伴卡身份、检查并绑定、绑定完成 | 格兰特利饰演查理；姓名、职业、一项特点 | 头像定点衔接人物卡姓名；用卡面替换保留同一视觉位置。建卡表单只取关键步骤 |
| S03／00:24–00:36 | 选景选项出现、点选、场景名与开场叙述 | 一个可读的地点名和一句开场 | 先让观众看到选择，再出现地点结果；记录状态等待不放入成片 |
| S04／00:36–00:54 | 一条调查行动、对应线索、一次检定与结果 | 动作—线索—结果 | 以稳定文字镜头交替；结尾留 2–3 秒看清判定结果 |
| S05／00:54–01:07 | 右侧主场景和嵌套子场景、参与者、子场景中行动 | 从哪里进入哪里、谁在里面 | 局部放大右侧层级；沿父项到子项加一条短引导线，随后回到正文 |
| S06／01:07–01:27 | 同一场战斗的队列、同伴行动、骰子、伤势、脱困结果 | 谁采取行动、代价、结果 | 先给 2 秒场景定位，再用 1.5–3 秒细节镜头；关键结果停留 3 秒。保留一次失败或伤势，使后面的情绪有依据 |
| S07／01:27–01:42 | 从跑团切至该同伴单聊、一个问题、一句回应、回到跑团 | 角色知道刚才发生了什么，并有自己的看法 | 头像位置衔接；问题短显，回复 1–2 行停留 5–7 秒；末尾用“继续同行”小字接回跑团 |
| S08／01:42–02:10 | 最终场景、结束叙述、完成报告首页、旅程、后传、检定／战斗回顾 | 一起走到结局、故事和人物留下了记录 | 最终场景约 8 秒；报告首页 5 秒；旅程 4 秒；后传 6 秒；两种统计共 5 秒。正文长页不要求通读 |
| S09／02:10–02:28 | 再次进入单聊、对应的回味、一个真实的告别或肯定句 | 从事件复盘转向共同经历 | 减少剪切，突出真实回复；可用前面动作 0.5–1 秒闪回，再回到回复。数值变化不是本段主角 |
| S10／02:28–02:40 | 新跑团的同行档案、已完成《古树林中》、勾选相同伙伴、Logo | 与你共同完成的记录，和下一次选择 | 对齐 S01 构图；先读到已有记录，再勾选伙伴。最后 4–5 秒呈现 GalChat 1.1 与片尾文案 |

片尾文案候选：“故事落幕。下一次，仍与你同行。”

主片中间仅放少量章节短句，例如“一同启程”“深入未知”“共同面对”“故事仍在继续”。章节文字每次只说一个意思，功能名称由真实 UI 承担。

**录屏设置与拍摄动作**

1. 先做 10 秒测试片，检查源文件真实像素、帧率和中文清晰度。优先录到 2560×1440 或更高的实际像素；若设备只能提供较低分辨率，就增加局部近景，不能靠放大导出来补细节。
2. 使用固定窗口大小、浏览器缩放与侧栏宽度。录制区域只包含应用内容；浏览器标签、地址栏、系统菜单和 Dock 排除在取景外。先以实际页面文字可读性决定缩放，再锁定。
3. Mac 可用 Shift–Command–5 的“录制所选部分”，麦克风关闭，音乐留到后期加入。关闭录屏工具的鼠标点击圆圈；后期只给关键点击加统一提示。录屏工具是否能固定帧率要实测，最后统一为 30 fps；若确实捕获到 60 fps，可留作慢速鼠标移动与动效素材。
4. 录制前手动打开需要的页面并定位消息，等图片、字体和历史记录加载稳定。避免把寻找按钮、快速滚动长文和等待模型的全过程放进镜头。
5. 每次操作前静止 2 秒，只做一个动作，动作结束后停 4 秒。主要文字另留 6–8 秒稳定镜头。每个关键状态录一份带操作的版本，再录一份鼠标移到内容外的稳定版本，并保存 PNG。
6. 需要真实生成的镜头可以长录，完成后记下可用片段时间。成片保留输入、短暂生成提示和完成结果，跳过中间等待；读字部分不要加速。
7. 同一条问答与同一场战斗记录在素材备注中写清会话、角色、事件和结果。拍摄会话与旧归档素材分开标记，剪辑时核对来源。
8. 当前角色多为文字头像。统一使用实际头像样式完成连贯镜头即可；若以后加入立绘，应整套更换并补拍相关画面，避免同一角色外观反复变化。

Apple 官方录屏说明：https://support.apple.com/zh-cn/102618

**二维动效规则**

沿用当前 UI 配色：纸色 #f4f1ea、墨色 #252724、深绿 #294f49、酒红 #8a3f48、琥珀 #b98542。酒红只强调伤势或失败，琥珀强调线索，其他大部分画面保持纸色与深绿。片头片尾使用项目 Logo 资源；标题可用宋体呼应完成报告，辅助字沿用界面无衬线字体。

所有参数先按 1080p／30 fps 样片测试：

| 动效 | 如何制作 | 建议参数 | 放在哪儿 |
|---|---|---|---|
| 缓慢推进 | 对完整录屏或高分辨率定帧设置位置与缩放关键帧 | 4–6 秒内 100% → 103%–105%；缓入缓出 | 开场、人物卡、后传 |
| 局部聚焦 | 先建立全景，再切到重新构图的裁切镜头；必要时从源画面单独裁出目标层 | 焦点切换约 0.4–0.6 秒；读字时停住；局部重录优先于过度放大 | 卡片姓名、线索、子场景 |
| 同一元素衔接 | 前后镜头以同伴头像或姓名为固定位置，叠化背景；位置差用短移动补齐 | 0.4–0.7 秒；一次只移动一个主要对象 | 同伴 → 调查员；跑团 → 单聊 |
| 重点高亮 | 原录屏作底层，目标裁切层放上方，其余区域轻微压暗；加细框或下划线 | 背景压暗约 12%–20%；线宽 2 px；出现 0.25–0.35 秒 | 关键线索、检定结果、同行次数 |
| 摘录出现 | 从真实回复提取完整短句，放在独立版式中；不重新制作假的聊天气泡 | 透明度 0 → 100%，位移 12–20 px，0.4–0.6 秒；1080p 正文约 30–36 px、最多两行 | 两次单聊与人物后传 |
| 场景深入 | 在真实父子场景列表上加遮罩强调和短引导线，跟随真实状态切换 | 0.5 秒指向、2–3 秒停留 | 子场景段落 |
| 战斗重音 | 以真实骰子落定、伤势变化、角色行动出现作为切点；必要时局部光晕 | 强调 4–8 帧；避免持续抖动影响阅读 | 战斗，不用于整片 |
| 报告翻页 | 录实际“继续”按钮与页面切换，后期用窄纸色遮罩或短叠化连接 | 0.5–0.8 秒；每页先停再翻 | 完成报告 |
| 首尾呼应 | S01 与 S10 固定同一取景和主同伴位置，片尾突出已完成条目 | 记录停留 3–4 秒，最后 Logo 停留 4–5 秒 | 下一次同行 |

首尾呼应使用真实存在的记录；如果开头拍摄时已经完成过跑团，不伪造次数从 0 变 1 的数据动画。片尾可以直接突出“与你共同完成 1 次跑团”。

动效控制：一屏一个焦点；关键文本展示期间镜头稳定；普通转场以直接切换或短叠化为主；章节转换才用完整遮罩。骰子使用产品自己的 3D 动画；报告保持正面可读，二维后期已足够表达纸质档案感。

**音乐与剪辑工作顺序**

1. 获取选定版本的合法音频文件，试听完整结构，标出入场、第一次推进、密集段、舒缓段、收束。原曲时间码与成片时间码分别记录。
2. 先用静帧、短标题和占位段落排出约 160 秒的粗剪；在乐句边界安排大段落转换。首次战斗给紧张感，最终场景承担共同走到结局的情绪重点；若音乐只有一处明显高潮，战斗保留局部加速，把最大的推进留到最终场景。
3. 用已有真实素材先做 20–25 秒样片：“一次行动与骰点 → 同伴回忆这件事 → 同行记录”。验证字是否看得清、跨界面是否能看懂、音乐是否有阅读空间，然后固定视觉样式。
4. 录完归档报告、已有单聊、人物卡和骰子回放，再集中补拍绑定、选景、子场景、战斗动态与中途交流。录制顺序可不同于影片顺序。
5. 替换占位素材，先完成只有切换、裁切和音乐的完整版本；确认故事与节奏后再做头像衔接、遮罩、高亮和字幕。
6. 导出 H.264／1080p／30 fps／SDR 的主片与无音乐版本；保留原片、PNG 和动效工程或脚本。最后在正常播放速度和手机尺寸检查字幕与 UI 关键文字，避免仅在暂停放大时可读。

录屏可以使用系统工具；后期采用剪辑轨道加二维位置、缩放、遮罩和文字图层。我后续制作时可用现有 FFmpeg 处理剪裁、合成与输出，较复杂的衔接用逐帧二维合成补足。具体渲染方式通过上述短样片验证后确定，当前不需要为此购买新软件。

音乐先保持纯 BGM。若增加非人声音效，只在少数关键骰子落定和翻页处使用，单独轨道控制，避免每次点击都发声。
